== SNS 사이트 DB 구조 정리 ==
- 각 테이블 명 앞에 'gymstory_' 를 붙여서 테이블 작성
- 총 5개 테이블: users, posts, comments, follows, likes

-------------------------------------
[1] gymstory_users (사용자 정보)
-------------------------------------
- SNS 로그인/프로필 화면에서 필요한 정보들

  컬럼명              타입              제약조건              설명
  ------------------------------------------------------------------
  id                 BIGINT           PK, AUTO_INCREMENT    사용자 고유번호 (자동 증가)
  username           VARCHAR(30)      UNIQUE, NOT NULL      @ 표시되는 고유 아이디
  email              VARCHAR(100)     UNIQUE, NOT NULL      로그인 이메일
  password           VARCHAR(255)     NOT NULL              비밀번호 (암호화 저장)
  display_name       VARCHAR(50)      NOT NULL              프로필에 보이는 표시 이름
  bio                TEXT             NULL                  소개글 (선택 입력)
  profile_image_url  TEXT             NULL                  프로필 사진 URL (Unsplash)
  created_at         TIMESTAMP        DEFAULT NOW()         가입일

-------------------------------------
[2] gymstory_posts (게시물 정보)
-------------------------------------
- SNS 피드/상세 화면에서 필요한 정보들

  컬럼명              타입              제약조건              설명
  ------------------------------------------------------------------
  id                 BIGINT           PK, AUTO_INCREMENT    게시물 고유번호 (자동 증가)
  user_id            BIGINT           FK → users.id         작성자 (사용자 번호)
  caption            TEXT             NOT NULL              게시물 글 내용
  image_url          TEXT             NOT NULL              Unsplash 이미지 URL
  likes_count        INT              DEFAULT 0             좋아요 수 (빠른 조회용 캐시)
  comments_count     INT              DEFAULT 0             댓글 수 (빠른 조회용 캐시)
  created_at         TIMESTAMP        DEFAULT NOW()         작성일
  updated_at         TIMESTAMP        DEFAULT NOW()         수정일

- [참고] likes_count / comments_count 는 실제 likes · comments 테이블 행 수와
  항상 일치해야 함. 좋아요·댓글 추가/삭제 시 함께 업데이트.

-------------------------------------
[3] gymstory_comments (댓글 정보)
-------------------------------------
- 게시물 댓글을 위한 정보들

  컬럼명              타입              제약조건              설명
  ------------------------------------------------------------------
  id                 BIGINT           PK, AUTO_INCREMENT    댓글 고유번호 (자동 증가)
  post_id            BIGINT           FK → posts.id         댓글이 달린 게시물 번호
  user_id            BIGINT           FK → users.id         댓글 작성자 번호
  content            TEXT             NOT NULL              댓글 내용
  created_at         TIMESTAMP        DEFAULT NOW()         댓글 작성일

-------------------------------------
[4] gymstory_follows (팔로우 정보)  ← 신규 추가
-------------------------------------
- 팔로우 / 언팔로우 기능 (필수 기능 3번)

  컬럼명              타입              제약조건              설명
  ------------------------------------------------------------------
  id                 BIGINT           PK, AUTO_INCREMENT    팔로우 관계 고유번호
  follower_id        BIGINT           FK → users.id         팔로우 하는 사람 (나)
  following_id       BIGINT           FK → users.id         팔로우 받는 사람 (상대방)
  created_at         TIMESTAMP        DEFAULT NOW()         팔로우 한 날짜

  - UNIQUE(follower_id, following_id) : 같은 사람을 중복 팔로우 방지

- [사용 예시]
  A가 B를 팔로우 → follower_id = A.id, following_id = B.id 행 추가
  A가 B를 언팔로우 → 해당 행 삭제
  내 팔로워 수 조회 → following_id = 내 id 인 행 개수
  내 팔로잉 수 조회 → follower_id = 내 id 인 행 개수

-------------------------------------
[5] gymstory_likes (좋아요 정보)  ← 신규 추가
-------------------------------------
- 좋아요 기능 (필수 기능 4번)
- likes_count 숫자만 저장하면 누가 눌렀는지 알 수 없고 중복 방지 불가 → 별도 테이블 필요

  컬럼명              타입              제약조건              설명
  ------------------------------------------------------------------
  id                 BIGINT           PK, AUTO_INCREMENT    좋아요 고유번호
  post_id            BIGINT           FK → posts.id         좋아요 누른 게시물 번호
  user_id            BIGINT           FK → users.id         좋아요 누른 사람 번호
  created_at         TIMESTAMP        DEFAULT NOW()         좋아요 누른 날짜

  - UNIQUE(post_id, user_id) : 한 게시물에 같은 사람이 중복 좋아요 방지

- [사용 예시]
  좋아요 누름 → (post_id, user_id) 행 추가 + posts.likes_count + 1
  좋아요 취소 → 해당 행 삭제 + posts.likes_count - 1
  내가 이미 좋아요 눌렀는지 확인 → post_id + user_id 로 행 존재 여부 확인

-------------------------------------
게시물 작성 방식
-------------------------------------
- 1단계: 내용(캡션) 입력
- 2단계: Unsplash API로 랜덤 이미지 여러 개 보여주기
- 3단계: 마음에 드는 이미지 선택 (새로고침으로 다른 랜덤 이미지들 볼 수 있음)
- 4단계: 선택한 이미지 링크를 gymstory_posts 테이블의 image_url에 저장

-------------------------------------
테이블 연결 관계 (ERD 요약)
-------------------------------------

  gymstory_users (1) ─────── (N) gymstory_posts
      한 사용자가 여러 게시물 작성 가능

  gymstory_users (1) ─────── (N) gymstory_comments
  gymstory_posts  (1) ─────── (N) gymstory_comments
      한 게시물에 여러 사용자가 댓글 작성 가능

  gymstory_users (N) ─── gymstory_follows ─── (N) gymstory_users
      사용자 간 팔로우 관계 (N:M 중간 테이블)

  gymstory_users (N) ─── gymstory_likes ──── (N) gymstory_posts
      사용자와 게시물 간 좋아요 관계 (N:M 중간 테이블)
